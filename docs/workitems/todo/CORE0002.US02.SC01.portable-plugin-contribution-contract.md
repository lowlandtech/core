## Outcome and scope

Centralize only portable plugin identity, target, manifest/contribution and immutable binding contracts in a Core-produced package consumed by Plugins and Backend. Inventory the currently published Plugins Domain API before moving any type; preserve versioned manifests, package identity, content hashes and compatibility with existing deployed packages. Keep NuGet orchestration, activation registry, deployment verification, host dispatch and graph execution with their current owners.

## Acceptance criteria

- [ ] UAC01: The shared contract describes a versioned backend-api or frontend contribution and its definition files without executable CLR type names supplied by untrusted data.
- [ ] UAC02: Plugins and Backend consume one exact contract package version; old published manifests remain readable or receive an explicit versioned migration/refusal.
- [ ] UAC03: A package-only producer/consumer test verifies manifest, contribution ownership and content-hash validation without source checkout references.
- [ ] UAC04: New contract assembly remains free of EF Core, NuGet runtime, ASP.NET and host activation dependencies.
