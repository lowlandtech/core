## Outcome and scope

Decide where a projection/checkpoint metadata seam for a transition belongs and
own that decision in the Core repository: a host service that records and
replays against the unchanged `gs.transition/v1` contract, or a versioned
canonical extension of the contract itself.

This scope records the decision, the inventory of the seams that already
exist and the compatibility refusals of the v1 contract. It does not change the
v1 contract, does not add a member, a trigger, an effect or a schema to it,
does not publish a package and does not own a host runtime.

The request came from the Composition lane, which found that
`TransitionAspectSet` carries no portable projection/checkpoint metadata and
that a trigger executes an effect and therefore cannot be a replay hook. The
lane asked for the source-owned minimal fit decision, the current contract
seams, the compatibility constraints, and the source scope and the disposition
of the decision.

## The minimal fit decision

**Host service. The v1 contract stays byte identical.**

The composition runtime projects and replays the transition history that it
owns, so the metadata it needs does not have to be portable between hosts. A
host service that records the projection of a case and replays the transition
by re-executing the graph satisfies that need without a single canonical byte
changing. A versioned canonical extension is the right fit only when a
checkpoint must be resumed by a host that did not produce it, because then the
metadata is part of the contract rather than part of a host.

The v1 contract leaves no seam that a projection could occupy without
breaking it:

- **The aspects object is byte-bearing.** `TransitionAspectSet` has nine
  members in a fixed wire order, and the canonical serialized form of a
  document is the form a content hash is computed over. A new member changes
  the canonical bytes of every document that carries it, and therefore every
  content hash, every published manifest and every parity fixture.
- **The trigger pair is closed.** A transition carries exactly the `::start`
  and the `::end` trigger, the start effect is one of `graph.walk`,
  `component.list` or `server`, and the end effect is `graph.persist`. A
  trigger carries an effect name only: it is not a replay hook and it carries
  no payload, and there is no free-form effect name left for one.
- **The schema is closed.** The validator refuses every schema other than
  `gs.transition/v1` with the named refusal `SchemaUnsupported`.
- **A capability is a reference, never an implementation.** A capability key
  names a service that the host has registered, and the admission refuses a
  capability that the host does not know with `CapabilityUnknown`.

The host service therefore uses the seams that the contract already offers:

| What the host needs | The seam that already exists |
|---|---|
| The observable projection of a case | `TransitionCase.Expected`, `Outcome` and `Diagnostic`, carried as data |
| The identity of the document that is replayed | the content hash over `TransitionContractDocument.Canonicalize` |
| The state that only the host knows | `TransitionAdmissionRequest.ExpectedOwner`, `ExpectedScope`, `KnownCapabilities` and `DeclaredContentHash`, with `TransitionContractValidator.ScopeEquals` |
| A named service that the host registers | a capability key, which is a reference and never an implementation |

## The compatibility refusals of the v1 contract

Core refuses the following, and each refusal is a property of the contract
rather than a preference:

1. No new member in `TransitionAspectSet` of `gs.transition/v1`. It changes
   the canonical bytes and every content hash computed over them.
2. No third trigger and no free-form effect name in v1. The trigger pair is
   exactly two and the effect vocabulary is closed.
3. No second canonical producer of the projection contract. The canonical
   transition contract belongs to Core alone; the Composition runtime consumes
   it, and a package of the Composition lane never becomes the contract.
4. No projection payload smuggled into `TransitionCase.Input` or
   `TransitionCase.Expected`. Those carry the observable data of a case, and
   reading them as a control surface gives two owners of one wire format.
5. No republication of the Core package for this decision. The v1 contract is
   unchanged, so the published candidate stands and the consumer cutover is
   untouched.

## When the versioned canonical extension is the right fit

A `gs.transition/v2` is the correct answer when a checkpoint must be resumed
by a host that did not produce it. That scope would carry a new schema, a new
aspects member with a new wire order, a new content-hash generation, a new
validator path, a new source-generated serialization context, a new immutable
`LowlandTech.Core.Contracts` version and the consumer migration of every host
that reads documents. It is a breaking producer scope and not a minimal fit,
so it is coordinator-owned refinement of this scope rather than a decision that
this proposal makes on its own.

The Composition lane requests that scope with evidence, and Core refines this
scope into the v2 producer scope when the request carries it.

## Acceptance criteria

Coordinator-1 owns the refinement of these criteria; they are the proposed
observations of the decision, not a refined implementation contract.

- [ ] UAC01: The Core source records the seam inventory of `gs.transition/v1`
  and the exact refusal of another schema, with the executed Core proof that
  the host documents round trip byte-identically through the canonical writer
  and that a `gs.transition/v2` document receives `SchemaUnsupported`.
- [ ] UAC02: The decision names the host service as the minimal fit, names the
  observable data it uses, and lists the compatibility refusals of the v1
  contract.
- [ ] UAC03: No canonical byte of `gs.transition/v1` changes: the contract
  publishes no new member, trigger, effect or schema, the published Core and
  contract packages stay available and unchanged, and no package is published
  for this decision.
- [ ] UAC04: The disposition is returned to the Composition lane with the
  source link of this scope, and the portable-checkpoint case is named as a
  separate request to the coordinator with its recovery owner, so that no
  consumer migration is claimed from a Core-only result.
