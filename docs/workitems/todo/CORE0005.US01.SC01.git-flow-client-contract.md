## Outcome and scope

Complete the existing Core graph git-flow read contract so Coder SHEL0003-US01-SC01 can render merge requests and feature proposals without inventing states in the shell. Core owns `src/lib/Plugins/MergeRequestStatus.cs`, `GraphMergeRequest.cs`, `MergeRequestProcessor.cs` and `FeatureProposalDocument.cs`. Extend their published models and source-owned transitions while preserving existing persisted documents and package consumers. The Coder lane owns its shell rendering and interaction acceptance.

## Acceptance criteria

- [ ] UAC01: The merge-request contract distinguishes Open, Reviewing, Approved, Rejected, Merged and Abandoned with stable wire values. Existing Open/Approved/Rejected documents still deserialize to their original meanings; invalid or terminal transitions are refused by Core rather than hidden by Coder.
- [ ] UAC02: The Core processor exposes which live requests may be approved or rejected and prevents those actions after merge, rejection or abandonment. A request can reach the new Reviewing and terminal states through named Core-owned behavior rather than client-side enum assignment alone.
- [ ] UAC03: `FeatureProposalDocument` exposes a stable title, lifecycle status and Gherkin specification for Coder's gap surface. Legacy documents lacking those fields have an explicit compatible default or named migration/refusal; submit/discard are available only while Draft.
- [ ] UAC04: An isolated package consumer can compile and read the new contract through one immutable `LowlandTech.Core` package pin. Coder proves its SHEL0003 read and action surface separately; Core records that handoff without claiming Coder acceptance.

Preserve existing serialized values and callers rather than renaming or reordering the three published enum members.
