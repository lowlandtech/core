## The question

Compare Core-central and Plugins-central ownership of the shared, portable
contract surface from the Core source and package boundary: what moves and what
stays, the dependencies, the consumer impact, an estimate for each migration
cut, and a recommended direction with source links.

- **Core-central:** the portable, data-only contract surface stays in
  `LowlandTech.Core.Contracts`, produced by `core/src/contracts`.
- **Plugins-central:** that surface moves into `LowlandTech.Plugins.Domain`,
  produced by the Plugins lane.

## Acceptance criteria

- [ ] UAC01: The assessment compares both directions from the Core source and
  package boundary, and names for each direction the surface that moves and
  the surface that stays.
- [ ] UAC02: The assessment records the measured dependencies and the consumer
  impact per lane, taken from the published feed and from the source
  references, with no estimated figure that is not measured.
- [ ] UAC03: The assessment estimates every migration cut on the 1-40 scale
  with its assumptions and its cadence, and recommends one direction with
  source links.

## The measured surface

`LowlandTech.Core.Contracts` declares **no dependency** and publishes 54 public
types in three families:

| Family | Namespace | What it carries |
|---|---|---|
| Portable plugin declaration | `LowlandTech.Core.Contracts.Plugins` | the plugin identity, manifest, contribution, route, slot and definition-file declarations with their validator and writer |
| Graph contract | `LowlandTech.Core.Contracts.Transitions` | `gs.transition/v1`: the definition document, the state machine, the aspects, the capability reference, the admission request, the diagnostic and the validator |
| Session content | `LowlandTech.Core.Contracts.Sessions` | the session-content descriptor, the intent, the target vocabulary and the provider entry point, published 2026-11-01 |

`LowlandTech.Plugins.Domain` declares one dependency,
`LowlandTech.Core.Contracts [2026.10.4-20261031113000]` in its newest generation,
and carries the plugin runtime model: the package descriptor, the lifecycle
descriptor and the install receipt.

## What the feed shows

- 756 published packages resolve `LowlandTech.Plugins.Domain`: Plugins 597,
  Coder 80, Builder 59, Components 13, Harness 4, TinyTools 2, Raconteur 1.
- 89 published packages resolve `LowlandTech.Core.Contracts`: 81 Plugins-family
  packages through the Domain pin, 8 Composition packages. 77 declare
  `[2026.10.4-20261027143600]`, 4 declare `[2026.10.4-20261031113000]`, 7 and 1
  declare the bare lower bound of the same generations.
- Source references to the contract package: Plugins 55 occurrences in 15
  files, Composition 33 in 16, Backend 6 in 4, Harness 3 in 2 (documentation
  only, no source reference), Builder 2 in 2 (documentation only).
- The Harness resolves the Domain package at one exact version,
  `2026.10.1-20261029231326395491648` in `Directory.Build.props`, and that
  generation declares `[2026.10.4-20261027143600]`.
- The Backend host pins one exact shared contract version, so a host that
  declares a different exact generation reports NU1608. That is the measured
  reason the Backend reverted its adoption of the session-content contract on
  2026-11-01.

## The cuts

| Cut | What moves | Core | Plugins | Backend | Harness | Composition | Workspace |
|---|---|---|---|---|---|---|---|
| A0 | Nothing moves; the current shape holds | 0 | 0 | 0 | 0 | 0 | 0 |
| A1 | The session-content contract is published alone (delivered 2026-11-01) | 5 | 0 | 3 | 2 | 0 | 10 |
| B1 | The portable declaration family moves to the Domain package | 5 | 8 | 3 | 2 | 0 | 18 |
| B2 | The session-content family moves as well | 3 | 5 | 3 | 3 | 0 | 14 |
| B3 | The graph contract moves too and the contract package is retired | 8 | 8 | 5 | 5 | 5 | 31 |

Assumptions: one immutable contract generation per change; the Domain republish
lands in the same window as the contract generation; the host keeps one exact
contract version; the 756 packages that resolve the Domain package keep their
exact pins, so they re-resolve no further. The cadence is the lane cadence: the
Core lane publishes inside its own window, the Plugins lane republishes the
Domain package in its own window, and the Backend moves its host pin in its own
window, so one cut spans two to four lane windows rather than one commit.

## The recommendation

**Core-central, with the graph contract staying in Core whatever happens.**

The portable surface is already published from one dependency-free producer,
and the only real cost of a contract change is a one-step repin wave: the
Domain package carries the pin, and the 89 packages that reach the contract
package reach it through that pin. That wave exists today and is exactly what
stopped the Backend and the Harness adoption on 2026-11-01.

A Plugins-central cut does not remove that wave, it adds a package to it. The
Composition package would depend on a plugin package it does not own, the
Backend host would gain a plugin dependency under its one-exact-version rule,
and the Core contract producer would shrink to the graph contract alone or be
retired, which moves the host-facing contract that the Backend, the Harness and
the Composition bind today.

If the workspace wants one home for the plugin-facing contracts, the cheaper
direction is the opposite of B1: keep the portable declarations in the
dependency-free contract package and let the Plugins lane keep the runtime
lifecycle model it already owns.
