## Outcome and scope

Own the portable session-content contract in `LowlandTech.Core.Contracts`: the
versioned descriptor that a content-owning plugin publishes, the provider that
a host reads it through, and the vocabulary of the targets that the descriptor
may name.

This scope publishes the contract. It does not own a publisher, a host
boundary, a mount or a layout audit: the Backend keeps its publisher, the
Harness keeps the admission boundary and the mount, and the content-owning
plugin keeps its provider implementation.

## The ownership, decided

| What | Owner | Why |
|---|---|---|
| the versioned content descriptor | Core.Contracts | a data-only descriptor that a plugin publishes and a host reads; no host type and no framework type |
| the provider contract | Core.Contracts | the one entry point that a plugin implements and a host calls |
| the target vocabulary | Core.Contracts | both sides must agree on the spelling of a target |
| the publisher of the content | Backend | it is the host side of the publication |
| the admission boundary and the mount | Harness | host behaviour, not a wire contract |
| the layout field inventory | Harness | an audit of the host layout model |

The package is `LowlandTech.Core.Contracts` because it is the only Core package
of portable data-only contracts that the host and the plugin packages already
reference. The contract declares no route, no transition and no session wire
protocol of its own.

## The exact contract

The portable part of the Harness session-content model, published under the
namespace `LowlandTech.Core.Contracts.Sessions`:

```csharp
namespace LowlandTech.Core.Contracts.Sessions;

/// <summary>The targets a session content descriptor may name.</summary>
public static class SessionContentTargets
{
    public const string SessionContent = "session-content";
    public const string OuterShell = "outer-shell";
    public const string RootRouter = "root-router";
    public const string ExplicitHostSlot = "explicit-host-slot";
}

/// <summary>One optional contribution the provider offers to the shell.</summary>
public sealed record SessionContentIntent(string Kind, string Slot);

/// <summary>The versioned content descriptor of a provider.</summary>
public sealed record SessionContentDescriptor
{
    public const string SupportedVersion = "1.0.0";

    public required string Version { get; init; }
    public required Guid SessionId { get; init; }
    public Guid? ContextId { get; init; }
    public required string Renderer { get; init; }
    public required string RendererVersion { get; init; }
    public IReadOnlyList<string> Assets { get; init; } = [];
    public required string Target { get; init; }
    public IReadOnlyDictionary<string, string> Layout { get; init; } =
        new Dictionary<string, string>(StringComparer.OrdinalIgnoreCase);
    public IReadOnlyList<SessionContentIntent> Intents { get; init; } = [];
    public IReadOnlyList<string> Transitions { get; init; } = [];
}

/// <summary>The provider of the content of one session.</summary>
public interface ISessionContentProvider
{
    Task<SessionContentDescriptor?> GetAsync(Guid sessionId, CancellationToken cancellationToken = default);
}
```

The rules of the contract:

1. The descriptor is data only. It names the session it belongs to, the version
   of the contract it speaks, the renderer and the assets it carries, the
   content root it targets, the layout it contributes and the pinned
   transitions it references. It defines no route and no wire protocol.
2. The provider is the one entry point. A content-owning plugin registers it,
   and a host reads the descriptor of a session through it.
3. The target vocabulary is shared, the decision is not: the host decides
   whether a named target is admitted. A descriptor that names the outer shell
   or the root router is refused by the host, not by the contract.
4. The publisher of the content stays with the host that serves it, and the
   admission boundary and the mount stay with the host that owns them.

## The acceptance criteria

- [ ] UAC01: `LowlandTech.Core.Contracts` publishes the descriptor, the
  provider contract and the target vocabulary as data-only types with no host
  type and no framework type, and the portable plugin declaration surface of
  the package is unchanged by them.
- [ ] UAC02: The contract states the ownership split: the Backend keeps the
  publisher, the content-owning plugin registers the provider, and the Harness
  keeps the admission boundary, the mount and the layout inventory.
- [ ] UAC03: The Core acceptance executes the contract: a provider returns a
  descriptor for a session, a host reads it through the contract, and the
  descriptor carries the session, the renderer, the assets, the target, the
  layout and the intents as data.
- [ ] UAC04: The contract ships as a new immutable `LowlandTech.Core.Contracts`
  version; the published version stays available and unchanged, no version is
  overwritten, and the consumers that pin the package move their own pins.
- [ ] UAC05: The Backend and the Harness hold the source link of this scope and
  the exact contract, and neither waits on an acknowledgement from Core.

## External technical prerequisites

The Backend owns `SessionContentPublisher` and its own publication flow. The
Harness owns the admission boundary, the mount and the layout inventory, and it
keeps its host behaviour over the shared contract. Core owns the contract, the
canonical package version and the coordination of the pins that name it.
