## The request

Coordinator-1 asked whether the shared scenario grammar and the Core-owned layout
tool should support a browser-aware scenario base
(`20261125T214151185333Z-5dd0e1bc@coordinator-1`, source
`story-editor/docs/workitems/done/STED0106.parts-become-sheets.md`). Story
Editor's browser acceptance Facts use `PlaywrightFixture` and `IAsyncLifetime`
and cannot meet the shared Given/When/Facts layout as it is written; "cosmetics
would fake compliance". Story Editor has `STED0106-US04` as the first consumer
and carries its use case in its own lane-owned TODO. The request is a bounded
tooling-contract question, not a behavior-acceptance bypass.

## The decision

**Yes: the shared grammar should admit a browser-aware scenario form, and the
tool needs no change.** The form keeps every existing rule and names no browser
type:

1. The scenario declares exactly one `[Given]` and one `[When]`, as overrides of
   the shared base or as annotated methods that the scenario invokes exactly once
   before its Facts run (`IAsyncLifetime.InitializeAsync` or an equivalent
   lifetime hook).
2. The Given/When code is visible in the scenario source and executes the real
   setup and action; it may delegate to a lane-owned use case and may receive the
   browser or page of a lane-owned fixture.
3. The scenario owns the browser fixture through its own collection/lifetime
   mechanism; the grammar names no Playwright, browser or host type.
4. Every Fact stays `[Then]` + one unique `[Trait("UAC", ...)]` + `[Fact]` + one
   expression-bodied direct assertion, exactly as the canonical form.
5. The path, namespace, class name, single type and line limit are unchanged.
6. The browser fixture and its collection are lane-local infrastructure; the
   shared grammar neither provides nor forbids a base class for them.

The canonical `UseCaseScenario<T>` form stays the default. The browser form is an
explicit alternative, not a replacement.

## Detection limits

- The gate proves the declaration and the shape, not that the Given and When
  actually ran; a lifetime hook that never calls them would still pass the shape
  check. Runtime proof stays the browser Fact's own execution, and the lane's
  acceptance must show the page/state observations.
- A helper or base-class file that itself carries `[Given]`/`[When]` attributes
  is classified as a scenario by the current discovery rule. Story Editor's
  `Infrastructure/Architecture/LaneBoundary.cs` is measured that way today
  (`invalid-scenario-path`, `invalid-class-name`). That is a discovery limit of
  the tool, not a browser issue; the fix is a Core-owned rule change and is not
  part of this proposal.
- The grammar cannot prove that the browser fixture owns an isolated host or
  page; that remains the lane's acceptance and the workspace browser-E2E gate.

  is explicitly not acceptance.

  hidden inside this change.
